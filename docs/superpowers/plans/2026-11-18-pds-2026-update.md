# PDS 2026 Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the PDS entry pages, database and PDF match CS Form 212 Revised 2026: A4, the official grid, correct numbering and captions, Monthly Salary, and continuation sheets C5–C11.

**Architecture:** A new `PdsPdfService` owns PDS data assembly and PDF rendering. The 1,181-line `pds/pdf.blade.php` becomes a shell plus four page partials and seven continuation partials. Two plain-PHP helpers (`PdsFormat`, `PdsRowSplitter`) replace the functions that were declared inside the view, so partials can be included more than once. Entry-page changes are small edits to existing React sections.

**Tech Stack:** Laravel 12, Pest (SQLite in memory, `RefreshDatabase` for `tests/Feature`), Blade with the existing Tailwind CDN script, Spatie Browsershot through `App\Support\PdfBrowsershot`, React 19 + TypeScript + Inertia.

**Spec:** `docs/superpowers/specs/2026-11-18-pds-2026-update-design.md`. Sheet reference: `docs/superpowers/specs/2026-11-18-pds-2026-workbook-dump.txt` (cell text and merged ranges of sheets C1–C11, extracted from `Files/CS Form No. 212 Revised 2026 Personal Data Sheet PDS.xlsx`; the merged ranges give the column grid).

## Global Constraints

- Paper: A4 portrait. Browsershot `->format('A4')->margins(11, 11, 8, 11, 'mm')`, so each page container must fit 188 mm × 278 mm.
- Row capacities (main page / continuation sheet): children 13 / 20 (C7); education 5 levels / 38 (C8); eligibility 7 / 24 (C9); work experience 24 / 34 (C6); L&D 17 / 44 (C5); voluntary work 9 / 29 (C10); other information 7 / 32 per column (C11); references 3 / none.
- Numbering: VI L&D = item 29, VII Voluntary Work = item 30, VIII Other Information = items 31–33.
- Captions: "(e-signature/digital certificate)"; notary line "(e-signature/digital certificate except for notary public)". Footer "CS FORM 212 (Revised 2026)"; "Page x of 4" only on the four main pages. Dates dd/mm/yyyy. Empty values print "N/A".
- Monthly Salary: `decimal(12,2)` nullable, printed "P21,877.00". Grade and step: one string matching `^\d{1,2}-\d$`, e.g. "24-2".
- Every printed data row carries `data-row="{section}"` (`child`, `eligibility`, `work-experience`, `learning-development`, `voluntary-work`, `other-info`, `reference`) and every continuation sheet's outer element carries `data-sheet="C5"` … `"C11"`, so tests can count them.
- Keep the Tailwind CDN script and utility classes. Do not edit `resources/js/routes/**`, `actions/**` or `wayfinder/` (Vite regenerates them). WES and the register-page consent text stay unchanged. No migration of existing PDS data.
- Access: the owner, or a user with role `admin`, `superadmin` or `hr`. Tests never run Chrome; HTTP tests mock `PdsPdfService`.
- Commit steps run only when the requester asks to commit. Stage named files only: the working tree already holds unrelated changes.
- UI process: before Tasks 2, 3 and 6–11, run `ui-consistency:finding-patterns` for the page being changed. After Task 11, run `ui-consistency:verifying`.

## Review Focus

1. A user with no PDS rows at all (every section empty, `personal` null) must render four pages of "N/A" without an exception. Pinned in Task 6.
2. Row-count boundaries: exactly at capacity prints no continuation sheet, capacity + 1 prints one, and a large count prints several. Pinned in Tasks 4 and 11.
3. HTML typed into a field (`<b>x</b>` as a position title) prints escaped. Pinned in Task 8.
4. Salary typed as "P21,877.00", or a grade without a step ("24"). The form strips the input to digits and the server rejects what is left. Pinned in Tasks 1 and 2.
5. Very long text in a cell makes a row grow and could push a page into a second sheet of paper. This needs Chrome, so it is checked by hand in Task 12.
